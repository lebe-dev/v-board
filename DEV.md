# Разработчикам

В проекте используется утилита [just](https://github.com/casey/just).

```bash
# Собрать релизную версию
just release

# Залить текущую версию на телефон подключённый через USB
just deploy
```

Все команды: `just --list`.

## Настройки сборки

Настройки сборки читаются из окружения или из файла `.env` в корне репозитория. Образец лежит в
`.env.example`.

## Подпись релиза

Release-сборка подписывается ключом проекта. Без ключа `just release` останавливается с
подсказкой, что заполнить.

1. Создайте ключ: `just release-key`. По умолчанию он сохраняется в
   `~/.config/v-board/release.jks`, пароли спросит `keytool`.
2. Заполните в `.env` переменные `RELEASE_KEYSTORE_FILE`, `RELEASE_KEYSTORE_PASSWORD`,
   `RELEASE_KEY_ALIAS` и `RELEASE_KEY_PASSWORD`.
3. Сделайте резервную копию ключа и паролей. Обновление ставится только поверх сборки с тем же
   ключом: если ключ потерян, приложение придётся удалить вместе с данными.

## Словарь пар слов

Экспериментальному движку slide to type нужен словарь пар слов из русской Википедии. Его нет
в git, он собирается командой `just bigrams` в `build/bigrams/assets/dict/ru.bigrams`.

- Debug-сборка (`just build`, `just deploy`) кладёт словарь в APK.
- Release-сборка его не содержит: приложение скачивает `ru.bigrams.gz` из GitHub-релиза своей
  версии и сверяет размер и SHA-256, вычисленные из того же файла при сборке.
- `just release` кладёт `ru.bigrams.gz` в `dist/` рядом с APK. При публикации релиза
  `vX.Y.Z` приложите оба файла, иначе загрузка словаря в этой версии не заработает.
- После обновления release-сборка сама загружает в фоне словарь своей версии, если у пользователя
  был загружен словарь прежней. Если в релизе словаря нет, старый удаляется: новой версии он не подходит.

## Обновления из GitHub-релизов

Страница "Обновления" в настройках берёт последний стабильный релиз через GitHub API
(`/repos/lebe-dev/v-board/releases/latest`), поэтому пре-релизы и черновики пользователям не
предлагаются.

- Тег релиза `vX.Y.Z` должен совпадать с `versionName`: по нему сравниваются версии.
- К релизу прикладывается ровно один `.apk`, его ставит приложение. Размер и SHA-256 берутся из
  данных GitHub о файле.
- APK должен быть подписан тем же ключом, что и установленная сборка, иначе приложение его не
  ставит и предлагает открыть страницу релиза. Debug-сборки поэтому из релизов не обновляются.
- `versionCode` не должен уменьшаться: Android не ставит сборку с меньшим `versionCode`.

## Коммиты в проекте

Проект использует стандарт [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/) для оформления коммитов.
Используйте английский язык без описаний и указания соавторства к коммитам.
